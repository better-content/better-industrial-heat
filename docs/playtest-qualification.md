These are source capabilities, not proof that every integration works in the full pack or that players can acquire everything in survival.

## Heat conservation change and qualification boundaries

The former 20-tick snapshot neighbor-average controller was non-conservative on unequal-degree networks: with external effects disabled, a 300-heat hub and three 100-heat leaves changed from **600 to 720** heat in one round at legacy strength 0.30. The retained `PipeThermalStepMath` helper still supports that historical operation for external callers/tests; the runtime controller now supplies **no neighbor influence** and performs only ambient blending, adjacent cold-source pull, passive loss and bounds. The config key `pipe_behavior.network_equalization_strength` remains present for compatibility, but does not govern runtime transfer. The sole native neighbor path is `HeatBlockEntity.transferAround` (four-tick pipe exchange), with extract-before-credit and actual acceptance/refund, loaded-neighbor checks and changed-endpoint-only heat sync from the exchange helper. Standalone firebox generation/burn/fuel, steady-strength boiler consumption, constant-temperature source reset and optional transducer energy/heat changes retain independent machine-state updates only on actual change. Loaded cross-chunk peers remain eligible; unloading a neighbor does not force-load it. Some old networks benefited from duplicated heat and may produce **less heat at their outputs**, so measure actual layouts before assuming existing throughput or progression is unaffected. No IDs, NBT layout, mappings, recipes or world-generation rules were changed; retain prior distributions and snapshot any disposable test world before testing.

Native fixtures repeat pair, hot/cold hub, chain and loop transfer calls with zero environmental inputs at every simulated 20-tick controller round; this exercises the production exchange and controller method, but is not a many-player tick-cost benchmark or a full client/network packet count. Ambient/source/loss were also checked independently in a native fixture. The real scheduling/event coverage remains limited by the existing headless fixture. The native transfer/source-resolver seams inject an unloaded neighbor and assert that no entity/cold-source state is queried, while loaded neighbors exchange/resolve normally; native callback capture asserts changed-endpoint and machine-self updates, and equilibrium silence. This does **not** unload an actual server chunk or measure real client packet counts; those checks remain unrun. Existing helper floor/partial-acceptance tests and native capability tests remain in place.
